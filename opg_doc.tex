\begin{abstract}
This document is a rigorous, math-first description of the current model forward pass and training loss as implemented
in \texttt{train\_gpt.py}. The core clarification is that the model contains \emph{two distinct iteration axes}:
(i) a \textbf{self-refinement loop} that feeds predicted token distributions back into the \emph{input embedding}, and
(ii) a \textbf{RevDEQ coupled-state loop} that iterates the \emph{hidden state} to approach a fixed point of a learned update
function. The specification below is intended to be self-contained and auditable against the code.
\end{abstract}

\section{Practical defaults (code defaults; throughput-oriented)}
\label{sec:throughput}
\paragraph{Goal.}
The defaults in \texttt{Hyperparameters} are throughput-oriented while maintaining DDP correctness and evaluation parity.
Some knobs are \emph{time-gated} (refinement, router health scaling) to reduce early instability and emphasize final health.

\paragraph{Defaults (as of 2026-04-15).}
\begin{itemize}
  \item \texttt{train\_batch\_tokens = 524288}, \texttt{train\_seq\_len = 2048} (global tokens/step; per-rank tokens scale with world size).
  \item \texttt{torch.compile(shared\_block, dynamic=False)} is attempted by default for throughput; it is skipped only when
        running DDP with \texttt{deq\_backward="unroll"} (compile+DDP+unroll incompatibility in current PyTorch).
  \item DEQ iteration count uses K-jitter by default: a shuffle-bag over \texttt{deq\_k\_jitter\_set=(4,8,16)} with broadcast from rank 0 each step.
  \item Self-refinement is ramped in late: \texttt{num\_refinements} is set to 0 until \texttt{time\_frac} exceeds
        \texttt{num\_refinements\_ramp\_frac} (default 0.85), then enabled and the refinement mixing coefficient ramps up.
  \item Router health pressure increases late: \texttt{health\_scale} ramps linearly from 1.0 to 5.0 over the final 30\% of wallclock
        (from \texttt{time\_frac}=0.70 to 1.00).
\end{itemize}

\paragraph{Terminology note.}
The script uses \texttt{num\_layers} as the default DEQ iteration count $K$; it is not a stack of distinct blocks.
The backbone is a \emph{single shared} transformer block iterated $K$ times inside the RevDEQ solver.

\section{Notation (shapes and conventions)}
\paragraph{Discrete inputs and targets.}
Let $V$ be the vocabulary size, $B$ the batch size, and $T$ the sequence length.
Inputs and targets are integer token IDs:
\[
  x \in \{0,\dots,V-1\}^{B\times T},\qquad
  y \in \{0,\dots,V-1\}^{B\times T}.
\]
In training, $y$ is the next-token target corresponding to $x$ (data windowing/stride is handled outside the model).

\paragraph{Embeddings and states.}
Let $d$ be the model dimension and $E\in\mathbb{R}^{V\times d}$ be the token embedding matrix.
The model operates on:
\[
  x_0 \in \mathbb{R}^{B\times T\times d}\quad\text{(input embedding to the backbone)},\qquad
  z \in \mathbb{R}^{B\times T\times d}\quad\text{(hidden state)}.
\]

\paragraph{Normalization notation.}
The code uses both parameter-free RMS normalization (\texttt{F.rms\_norm} via \texttt{\_rms\_norm}) and learnable RMSNorm modules
(\texttt{RMSNorm}, with an elementwise weight). In the math below, we write:
\[
  \mathrm{rms\_norm}(\cdot)\ \text{for parameter-free normalization},\qquad
  \mathrm{RMSNorm}(\cdot)\ \text{for a learnable RMSNorm module}.
\]

\paragraph{Distributions.}
The model produces two log-probability tensors:
\[
  \log p_{\text{CTP}} \in \mathbb{R}^{B\times T\times V},\qquad
  \log p_{\text{NTP}} \in \mathbb{R}^{B\times T\times V},
\]
which are consumed in two ways:
\begin{itemize}
  \item for training losses, they are used directly in a negative log-likelihood;
  \item for self-refinement, the code converts them into \emph{valid} probability distributions by
    exponentiating and renormalizing in fp32.
\end{itemize}

\paragraph{Two iteration axes.}
We distinguish:
\begin{itemize}
  \item \textbf{Self-refinement iteration} $r\in\{0,1,\dots,R\}$ where $R=\texttt{num\_refinements}$.
    This is the outer loop: \emph{solve $\rightarrow$ predict $\rightarrow$ soft-embed $\rightarrow$ re-solve}.
  \item \textbf{DEQ iteration} $k\in\{0,1,\dots,K-1\}$ where $K=\texttt{num\_layers}$.
    This is the inner loop: coupled-state iteration that repeatedly applies a learned update function.
\end{itemize}

\section{End-to-end forward algorithm (single source of truth)}
\label{sec:forward}

\paragraph{Overview.}
The model maps token IDs $x$ to final hidden states $z^{(R)}$ via a backbone solve that may be repeated for refinement.
It then maps $z^{(R)}$ to two distributions (CTP and NTP) via a dual \textbf{MoSHead}.
Training losses are computed \emph{only on the final output} after the last refinement solve.

\paragraph{Pseudocode (matches \texttt{GPT.\_encode} + \texttt{GPT.\_run\_backbone}).}
\begin{lstlisting}
Inputs: token IDs x [B,T], targets y [B,T]
Hyperparams: R=num_refinements, K=num_layers, beta=deq_beta

# 1) Base input embedding
x0^(0) = rms_norm( Emb(x) + BigramHashEmb(x) )   # BigramHashEmb may be disabled
prev_soft = x0^(0)
z_init = x0^(0)

for r = 0..R:
  if r > 0:
    # No-grad: predict -> prob dist -> soft embed (topk=64)
    p_mix = MixProb( p_CTP(z^(r-1)), Shift(p_NTP(z^(r-1))) )
    soft = SoftEmbedTopK(p_mix, E, topk=64)     # rms_norm applied inside
    alpha = refine_mix_alpha in [0, 0.5]        # ramps up when refinement enabled
    x0^(r) = alpha * soft + (1-alpha) * prev_soft
    prev_soft = stopgrad(x0^(r))
    z_init = x0^(r)                             # warm start from refined input
  else:
    x0^(0) already defined

  K_eff = (_deq_k_override if set else K)       # jitters during training; fixed for eval
  z^(r) = RevDEQ_Solve( f_theta, x0^(r), z_init, beta, K_eff )

# 2) Final head
h = RMSNorm(z^(R))
log p_CTP, log p_NTP = MoSHead(h)
loss = NLL(log p_NTP, y) + ... (aux losses)
\end{lstlisting}

\section{Outer loop: self-refinement over input embeddings ($r$)}
\label{sec:refinement}

\subsection{Initial input embedding ($r=0$)}
The initial embedding is:
\[
  x_0^{(0)} \;=\; \mathrm{RMSNorm}\!\left(E[x] + \mathrm{BigramHashEmb}(x)\right),
\]
where \texttt{BigramHashEmb} may be disabled (then it contributes $0$).

\subsection{From predictions to a valid refinement distribution ($r>0$)}
At the end of solve $r-1$, define $h^{(r-1)}=\mathrm{RMSNorm}(z^{(r-1)})$ and compute:
\[
  \log p_{\text{CTP}}^{(r-1)},\ \log p_{\text{NTP}}^{(r-1)} \;=\; \mathrm{MoSHead}(h^{(r-1)}).
\]
For self-refinement, the code converts each log-prob into a numerically stable probability distribution:
\[
  \mathrm{Prob}(\log p)[v] \;=\;
  \frac{\exp(\log p[v])}{\sum_{u=1}^{V}\exp(\log p[u])}\quad\text{(computed in fp32, then renormalized)}.
\]
Let $p_{\text{CTP}}^{(r-1)}=\mathrm{Prob}(\log p_{\text{CTP}}^{(r-1)})$.
Define a shifted next-token distribution so that position $t$ uses the previous token's next-token predictor:
\[
  p_{\text{NTP,shift}}^{(r-1)}[t] \;\equiv\;
  \begin{cases}
    p_{\text{NTP}}^{(r-1)}[0] & t=0,\\
    p_{\text{NTP}}^{(r-1)}[t-1] & t\ge 1.
  \end{cases}
\]
Then the mixed refinement distribution is:
\[
  p_{\text{mix}}^{(r-1)}[t] \;=\;
  \begin{cases}
    p_{\text{CTP}}^{(r-1)}[0] & t=0,\\
    \tfrac{1}{2}p_{\text{CTP}}^{(r-1)}[t] + \tfrac{1}{2}p_{\text{NTP,shift}}^{(r-1)}[t] & t\ge 1.
  \end{cases}
\]
Because both inputs are valid distributions, $p_{\text{mix}}$ is also a valid distribution in exact arithmetic.
The implementation still applies NaN/Inf guarding.

\subsection{Soft embedding from a top-$\kappa$ approximation}
\label{sec:softembed}
The code approximates the expected embedding under $p_{\text{mix}}$ using a top-$\kappa$ truncation
(default $\kappa=64$; notation uses $\kappa$ to avoid confusion with the DEQ iteration count $K$).
Let $\mathcal{S}_\kappa(t)$ be the indices of the top-$\kappa$ probabilities at position $t$.
Define a renormalized distribution over $\mathcal{S}_\kappa(t)$:
\[
  \tilde p_{\text{mix}}[t,v] \;=\;
  \frac{p_{\text{mix}}[t,v]}{\sum_{u\in\mathcal{S}_\kappa(t)} p_{\text{mix}}[t,u]}
  \qquad (v\in\mathcal{S}_\kappa(t)).
\]
The soft embedding is the expected embedding under $\tilde p_{\text{mix}}$:
\[
  x_{\text{soft}}^{(r)}[t] \;=\; \mathrm{RMSNorm}\!\left(\sum_{v\in\mathcal{S}_\kappa(t)} \tilde p_{\text{mix}}^{(r-1)}[t,v]\ E[v]\right).
\]
Implementation note: the expected embedding is computed in chunks to avoid materializing a large $[B,T,\kappa,d]$ tensor.

\subsection{Refinement coupling (input embedding update)}
Refinement updates the \emph{input embedding} for the next solve by mixing the new soft embedding with the previous refined input:
\[
  x_0^{(r)} \;=\; \alpha\,x_{\text{soft}}^{(r)} + (1-\alpha)\,x_0^{(r-1)},
\]
where $\alpha=\texttt{\_refine\_mix\_alpha}\in[0,0.5]$ is ramped up when refinement is enabled.
The previous refined input is detached in code (\texttt{prev\_soft = x0\_refined.detach()}), so gradients do not flow through earlier refinement steps.

\paragraph{One-hot as a special case.}
The $r=0$ embedding path corresponds to a delta distribution at each position
($p(v)=\mathbb{1}[v=x_t]$), whose expected embedding is exactly $E[x_t]$.

\section{Inner loop: RevDEQ coupled-state solver over hidden states ($k$)}
\label{sec:deq}

\subsection{Coupled-state fixed-\texorpdfstring{$K$}{K} iteration (explicit unroll)}
Within a single refinement solve $r$, the backbone runs $K$ coupled-state iterations with relaxation parameter $\beta\in(0,1)$.
It maintains two states $y_k^{(r)}$ and $z_k^{(r)}$ (both in $\mathbb{R}^{B\times T\times d}$) and applies $f_\theta$ twice per step:
\begin{align}
  y_{k+1}^{(r)} &= (1-\beta)\,y_k^{(r)} + \beta\, f_\theta\!\left(z_k^{(r)}, x_0^{(r)}\right),\\
  z_{k+1}^{(r)} &= (1-\beta)\,z_k^{(r)} + \beta\, f_\theta\!\left(y_{k+1}^{(r)}, x_0^{(r)}\right),
\end{align}
for $k=0,\dots,K-1$.

\paragraph{Warm start and terminal output.}
The code uses $y_0^{(r)}=z_0^{(r)}=z_{\text{init}}^{(r)}$ and sets $z_{\text{init}}^{(r)}=x_0^{(r)}$.
The solve returns the terminal state $z^{(r)}\equiv z_K^{(r)}$ and also tracks $z_{K-1}^{(r)}$ for convergence diagnostics.

\subsection{Backward modes (same forward)}
The forward dynamics above are the same for both backward modes:
\begin{itemize}
  \item \texttt{deq\_backward="unroll"} (alias: \texttt{"autograd"}): explicit unroll retains activations and supports differentiable output-space regularizers.
  \item \texttt{deq\_backward="revdeq"}: uses a custom memory-efficient backward (\texttt{RevDEQFunction}) that reconstructs states in reverse.
    FP64 add/sub is used inside reconstruction for numerical stability; reconstruction error is logged only for this mode.
\end{itemize}

\section{Update function \texorpdfstring{$f_\theta(z,x_0)$}{f(z,x0)} (Block)}
\label{sec:f_theta}

\subsection{Input injection via a token-local gate (experts only)}
Let $z_{\text{in}}\in\mathbb{R}^{B\times T\times d}$ denote the current DEQ state and $x_0$ the (possibly refined) input embedding.
The block computes a \emph{token-local} injection gate:
\[
  g_{\text{inj}} \;=\; \sigma(\mathrm{inj}( \mathrm{RMSNorm}(z_{\text{in}}))) \in (0,1)^{B\times T\times 1}.
\]
Injection is applied only to the \emph{expert feature inputs} (not to routing decisions):
\[
  x_{\text{router}} = z_{\text{in}},\qquad
  x_{\text{expert}} = z_{\text{in}} + g_{\text{inj}}\odot x_0.
\]
Routers read $x_{\text{router}}$ (state-only). Experts read $x_{\text{expert}}$ (state + gated embedding).

\subsection{Component-level dense routing (Soft Dense Routing)}
The block contains two dense MoE components: attention and MLP. Each has its own router.
For a \emph{normalized} router input $h_n\in\mathbb{R}^d$ (in code, produced by a learnable \texttt{RMSNorm} in the block),
routing weights are:
\[
  w(h_n) \;=\; \mathrm{softmax}\big(W_r\,h_n + b_{\text{expert}} + \log\sigma(W_g\,h_n+b_g)\big)\in\Delta^{E-1},
\]
so $w\in\mathbb{R}_{\ge 0}^{E}$ and $\sum_{e=1}^{E} w_e = 1$ (pure softmax; no post-softmax sigmoid gating).
All experts process all tokens; the routed update is the convex mixture of expert outputs.

\paragraph{Training-time router losses.}
Let $\bar w=\mathbb{E}_{b,t}[w_{b,t}]$. Each router tracks:
\[
  L_{\text{bal}}=\left\|\bar w-\tfrac{1}{E}\mathbf{1}\right\|_2^2,
\]
and a ``health'' barrier term that targets the final-only constraints (min-share and CV):
\[
  L_{\text{health}}=\mathrm{health\_scale}\Big(
    \lambda_{\min}\,\mathbb{E}_e\big[\max(0,\tfrac{0.6}{E}-\bar w_e)^2\big]
    + \lambda_{\mathrm{cv}}\, \max(0,\mathrm{CV}(\bar w)-0.20)^2
  \Big),
\]
where $\lambda_{\min}$ and $\lambda_{\mathrm{cv}}$ are router-specific weights (attention and MLP use different values in code).
(\texttt{health\_scale} ramps up late in wallclock.) Additionally, an out-of-graph bias controller updates
\texttt{expert\_bias} toward a target distribution that boosts experts below the min-share threshold.

\subsection{Parallel attention + MLP update (no learned residual gate)}
The block computes attention and MLP updates from the same pre-residual input and adds them:
\[
  z_2 \;=\; \mathrm{Norm}_{\text{attn}}(\Delta_{\text{attn}}) + \mathrm{Norm}_{\text{mlp}}(\Delta_{\text{mlp}}),
\]
then emits
\[
  f_\theta(z_{\text{in}},x_0)\;=\;\mathrm{RMSNorm}_{\text{post}}\!\left(0.5\,z_2\right).
\]
There is no learned ``gg'' residual gate in the current code; a constant-1.0 ``gg'' diagnostic is kept only for backward-compatible logging.

\subsection{MLA + gated attention (within $\Delta_{\text{attn}}$)}
\label{sec:mla}
The attention module is ``MLA-style'': it compresses K/V through a latent projection and uses a decoupled RoPE path.
From normalized input $u=\mathrm{RMSNorm}(x_{\text{expert}})$:
\begin{itemize}
  \item Queries: a single linear \texttt{c\_q} produces both $Q$ and per-head gate logits, then $Q$ is split into a RoPE slice and a no-RoPE slice.
  \item Keys/values: \texttt{c\_kv\_down} produces a latent K/V; $K_{\text{noRoPE}}$ and $V$ come from the latent, while $K_{\text{RoPE}}$ is projected directly from $u$.
  \item RoPE: apply rotary embedding only to the RoPE slices of $Q$ and $K$, then concatenate RoPE and no-RoPE parts.
  \item SDPA: use \texttt{scaled\_dot\_product\_attention} in causal mode (GQA when \texttt{num\_kv\_heads != num\_heads}).
  \item Gated attention: apply a head-specific sigmoid gate \emph{after} SDPA: $Y \leftarrow Y \odot \sigma(g_{\text{attn}} + b_{\text{gate}})$.
  \item Post-SDPA norm: apply RMSNorm to the gated attention output before expert mixing.
\end{itemize}

\subsection{MLP expert bank (within $\Delta_{\text{mlp}}$)}
The MLP path is an expert bank with a squared leaky-ReLU gate:
\[
  h = \mathrm{LeakyReLU}(xW_g;0.5)^2 \odot (xW_f),
\]
applied per expert, with per-expert RMSNorm on the hidden rank dimension before dense mixing and a per-expert down projection.

\section{Heads and losses (training objective)}
\label{sec:loss}

\subsection{CTP and NTP log-probabilities}
After the final refinement solve ($r=R$), compute:
\[
  h=\mathrm{RMSNorm}(z^{(R)}),\qquad
  \log p_{\text{CTP}},\ \log p_{\text{NTP}} = \mathrm{MoSHead}(h).
\]
CTP is trained to predict the current token $x$, and NTP predicts the next token $y$.

\subsection{Main negative log-likelihood losses}
The script uses \texttt{F.nll\_loss} on the log-probabilities:
\[
  L_{\text{NTP}} = \mathrm{NLL}(\log p_{\text{NTP}}, y),\qquad
  L_{\text{CTP}} = \mathrm{NLL}(\log p_{\text{CTP}}, x).
\]
The CTP weight is gated by the refinement ramp (early training uses $R=0$):
\[
  \lambda_{\text{CTP}} = 0.05\,R\cdot \mathrm{clip}\!\left(\frac{\alpha}{0.5},\,0,\,1\right),
\]
where $\alpha=\texttt{\_refine\_mix\_alpha}\in[0,0.5]$ is the refinement mixing coefficient.

\subsection{MoSHead (CTP+NTP) + FSQ + auxiliary metrics}
The head is a dual Mixture-of-Softmaxes with FSQ quantization in the low-rank space:
\begin{itemize}
  \item Each of CTP and NTP has a softmax gate over \texttt{num\_shared + num\_specialized} experts.
  \item Each expert maps $h$ to a rank-$r$ vector, applies FSQ ($L$ levels) via a tanh bound + STE rounding, then projects to vocab logits.
  \item The final distribution is a log-space mixture via \texttt{logaddexp} accumulation and renormalization.
\end{itemize}
The head also tracks (i) a balance loss on mean routing weights, and (ii) an orthogonality proxy used only if enabled by a coefficient.

\subsection{Block orthogonality auxiliary loss (optional)}
When enabled (periodically during training), the code computes a small auxiliary ``expert separation'' diagnostic on a short prefix
of tokens (default 64): it estimates per-expert mean outputs for attention and MLP expert banks and computes a mean off-diagonal
absolute cosine similarity. The loss is a soft barrier above 0.20:
\[
  L_{\text{block-ortho-aux}}=\tfrac{1}{2}\Big(\max(0,o_{\text{attn}}-0.20)^2+\max(0,o_{\text{mlp}}-0.20)^2\Big).
\]

\subsection{Total loss returned by \texttt{GPT.forward}}
The model returns:
\[
  L \;=\; L_{\text{NTP}} + \lambda_{\text{CTP}}L_{\text{CTP}}
  + \lambda_{\text{bal}}L_{\text{bal}}
  + \lambda_{\text{health}}L_{\text{health}}
  + \lambda_{\text{mos}}L_{\text{mos-ortho}}
  + \lambda_{\text{blk}}L_{\text{block-ortho-aux}},
\]
where the coefficients match code:
\[
  \lambda_{\text{bal}}=\texttt{bal\_loss\_coef},\quad
  \lambda_{\text{health}}=\texttt{router\_health\_coef},\quad
  \lambda_{\text{mos}}=\texttt{mos\_ortho\_out\_coef},\quad
  \lambda_{\text{blk}}=\texttt{block\_ortho\_aux\_coef}\cdot \texttt{\_block\_ortho\_aux\_coef\_scale}.
\]
\paragraph{Balance aggregation detail.}
In code, $L_{\text{bal}}$ includes (i) the attention-router and MLP-router MSE-to-uniform terms (weighted by \texttt{attn\_balance\_mult} and
\texttt{mlp\_balance\_mult}), and (ii) an additional $50\times$ multiplier on the MoSHead balance loss to prevent dead head experts.
